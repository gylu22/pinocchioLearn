# 轮式人形机器人 WBC 知识体系与技术路线

> 面向的当前系统：**cuRobo v2 全身轨迹规划 + ROS 2 桥接 + Isaac Sim 关节 PD 伺服**；
> **固定基座**（暂不考虑轮式底盘）；被控对象为 **4 个躯干关节 + 双臂 14 个关节（共 18 DoF）**。
> 目标：在不推翻现有规划/仿真链路的前提下，增加一层可在真机上复用的 WBC。

## 1. 三条先给结论

1. **固定基座 + 位置 PD 伺服的场景下，WBC 不需要浮动基/接触力优化**。它退化为“全身轨迹跟踪 + 冗余分解 + 约束投影”的加速度级控制器，18 维 QP 很小，Python 200–500 Hz 足够。
2. **WBC 的输出应该匹配伺服输入**。你的 Isaac 关节是位置/速度 PD，所以 WBC 输出 `q_des, qd_des`（可选重力/动力学前馈）最自然；如果以后要输出力矩，再把驱动切到 effort 模式。
3. **分层控制不是必须的**。对固定基座，单层加权 QP 通常够用；只有当任务冲突明显、需要严格安全优先级、或以后上浮动基/多接触时，才值得上 HQP（分层 QP）。

## 2. 推荐的目标架构

```
┌─────────────────────────────────────────────────────────────┐
│ 规划层：cuRobo v2（ROS 2，10–50 Hz）                          │
│  输入：/joint_states、世界模型、末端/躯干目标                  │
│  输出：trajectory_msgs/JointTrajectory(q, qd, qdd, t)        │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ WBC 层（ROS 2，200–500 Hz）                                  │
│  Pinocchio：FK / J / J̇ / M / h                              │
│  QP：末端位姿 + 躯干姿态 + posture + 关节/力矩限位             │
│  输出：q_des, qd_des（可选 tau_ff / 重力前馈）                │
└──────────────────────────┬──────────────────────────────────┘
                           │ sensor_msgs/JointState / Float64MultiArray
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 桥接层：ROS 2 Bridge（仿真） / 硬件驱动（真机）                │
└──────────────────────────┬──────────────────────────────────┘
                           │
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 伺服层：关节 PD（Isaac 物理步 / 真机驱动器）                   │
│  tau = Kp(q_des - q) + Kd(qd_des - qd)，带力矩限幅             │
└──────────────────────────┬──────────────────────────────────┘
                           │ /joint_states、/clock、/tf
                           └──────────────► 反馈回 WBC / 规划
```

**关键设计**：WBC 节点与“仿真/真机”解耦。仿真时它连 Isaac 的 ROS 2 bridge；真机上它连硬件驱动。上层 cuRobo 和下层 PD 都不需要改，只换中间的桥。

## 4. 当前系统里 WBC 的最小职责

固定基座、无接触时，WBC 每个控制周期只做四件事：

1. **采样参考**：从 cuRobo 的 `JointTrajectory` 插值出 `q_ref, qd_ref, qdd_ref`。
2. **算运动学量**：`computeJointJacobians`、`updateFramePlacements`、`computeJointJacobiansTimeVariation`。
3. **解 QP**：以 `qdd` 为变量，跟踪左右末端位姿、躯干姿态、posture，满足关节位置/速度/加速度/力矩限位。
4. **输出关节目标**：`qd_des = qd + qdd·dt`，`q_des = integrate(q, qd_des·dt)`，发布给 PD。

如果只做关节空间跟踪，第 3 步可以退化成插值器，甚至直接用 `joint_trajectory_controller`。**WBC 的价值在于第 3 步**：它能在多任务冲突、冗余、约束、笛卡尔精度上做得比“直接播轨迹”更好。

## 5. 建议的实施顺序（详细版见 05、06）

| 阶段 | 做什么 | 验收标准 |
|---|---|---|
| P0 | 统一模型/关节顺序/零位/单位；Isaac 与 Pinocchio 对同一组 q 做 FK 对比 | 末端位置误差 < 1e-6 m |
| P1 | 纯轨迹插值 + PD，跑通 cuRobo 静态目标 | 关节跟踪误差可接受，无超限 |
| P2 | 加 WBC：末端 + 躯干 + posture，输出 `q_des/qd_des` | 笛卡尔跟踪误差优于 P1 |
| P3 | 加约束：位置/速度/加速度/力矩限位 | QP 始终可行，无饱和 |
| P4 | 加前馈：重力 `tau_g`，再考虑 `M qdd + h` | 稳态误差明显下降 |
| P5 | 若需要：加权 QP → HQP（严格优先级） | 任务冲突时高优先级不被破坏 |
| P6 | 迁移真机：替换桥接、标定、安全层、低增益试跑 | 悬吊/低增益下稳定，再逐步放开 |
| P7 | 解锁轮式底盘：浮动基 + 接触约束 | 平衡/移动时 WBC 仍稳定 |

## 6. 术语约定

- **q / v / a**：广义位置 / 速度 / 加速度。固定基座时 `nq = nv = 18`；浮动基座时 `nq ≠ nv`（四元数）。
- **任务（task）**：希望控制的量，例如末端 6D 位姿、躯干 3D 姿态、关节 posture、CoM。
- **约束（constraint）**：必须满足的硬条件，例如关节限位、接触不滑动、摩擦锥、力矩上限。
- **WBC**：把任务和约束统一成一个（或一组）优化问题，求广义加速度/力矩。
- **HQP**：Hierarchical QP，分层二次规划，用严格优先级处理任务冲突。
- **PD 伺服**：关节级位置/速度闭环，`tau = Kp(q_des-q) + Kd(qd_des-qd)`。

## 7. 相关代码/工具

- Pinocchio：模型、FK、雅可比、`M/h`、CoM/centroidal、李群运算。
- OSQP / ProxSuite / quadprog：QP 求解器。
- TSID：现成的分层 WBC（基于 Pinocchio + eiquadprog）。
- Crocoddyl / Aligator：MPC / 轨迹优化。
- Isaac Sim ROS 2 Bridge：`/joint_states`、`/clock`、命令订阅。
- cuRobo v2：全身运动规划，输出关节轨迹。
