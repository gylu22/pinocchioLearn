# 03 · WBC 的技术路线

> 目标：把“WBC”这个词拆成几条可落地的路线，说明各自解决什么问题、代价是什么、适合谁。
> 读完后你应该能选出一条**当前阶段**的路线，并知道以后怎么升级。

---

## 1. 一张图看路线

```text
                          ┌─ 加权 QP（单层，软优先级）
                          │
        ┌─ 优化型 WBC ────┼─ 分层 QP / HQP（严格优先级）
        │                 │
        │                 └─ 多接触 / 摩擦锥 / 接触切换
        │
WBC ────┼─ 解析型 WBC ──── 操作空间控制（OSC）/ 任务空间逆动力学
        │
        ├─ 降维型 WBC ──── 质心动力学（Centroidal）+ 接触力分配
        │
        ├─ 预测型 WBC ──── 全身 MPC（DDP / 直接法）
        │
        ├─ 学习型 WBC ──── RL 策略（端到端，输出关节目标/力矩）
        │
        ├─ 交互型 WBC ──── 阻抗 / 导纳控制
        │
        └─ 运动学 WBC ──── 全身 IK（Pink 等），不含动力学
```

---

## 2. 路线详解

### 2.1 加权 QP（Weighted Whole-Body QP）

**做法**：所有任务放进一个 QP，用权重表达优先级。

```text
min_{qdd}  Σ_i w_i || J_i qdd + Jdot_i qd - xdd_i* ||² + w_r ||qdd||²
s.t.       关节/力矩/速度/接触约束
```

**优点**：

- 实现最简单，一个 QP；
- 求解快，18 DoF 可以到 500 Hz+；
- 任务和约束统一，容易加新任务。

**缺点**：

- 权重难调，量纲敏感；
- 不保证高优先级任务；
- 任务多时会出现“互相拉扯”。

**适合**：固定基座、任务不剧烈冲突、原型阶段。**这是你当前最合适的起点。**

**工具**：OSQP、ProxSuite、quadprog；自己写 200 行 Python 即可。

---

### 2.2 分层 QP / HQP（Hierarchical QP）

**做法**：任务按优先级排队，逐级求解；低优先级在高优先级零空间/可行域内优化。详见 [02-hierarchical-control.md](02-hierarchical-control.md)。

**优点**：

- 严格优先级，行为可预测；
- 安全/接触可以硬约束，任务不会被低优先级破坏；
- 人形/多接触 WBC 的主流。

**缺点**：

- 多级 QP，计算量大 2–5 倍；
- 每级都可能不可行，需要 slack/放松策略；
- 实现复杂。

**适合**：浮动基人形、多接触、任务冲突明显、安全关键。

**工具**：

- **TSID**（stack-of-tasks）：直接提供 task + contact + HQP，基于 Pinocchio；
- **mc_rtc / Tasks**：完整人形控制框架；
- 自己用 OSQP 做级联。

**你的阶段**：可以不用；等末端/躯干/posture 冲突明显，或上浮动基时再考虑。

---

### 2.3 操作空间控制（OSC）/ 任务空间逆动力学

**做法**：用动力学一致的伪逆，把任务空间力映射到关节力矩；低优先级任务通过零空间投影叠加。

```text
Lambda = (J M^{-1} J^T)^{-1}
F      = Lambda (xdd* - Jdot qd) + Lambda J M^{-1} h
tau    = J^T F + N^T tau_posture
N      = I - J^# J,   J^# = M^{-1} J^T (J M^{-1} J^T)^{-1}
```

**优点**：

- 解析、快、物理意义清晰；
- 适合“主任务 + 姿态”的机械臂/躯干控制；
- 阻抗控制可以自然叠加。

**缺点**：

- 不等式（限位、摩擦锥）难处理；
- 多任务/多接触表达式复杂；
- 奇异位形需要阻尼。

**适合**：机械臂操作、固定基座、任务数少。

**工具**：自己实现；Pinocchio 提供 `M`、`h`、`J`。

---

### 2.4 质心动力学 WBC（Centroidal WBC）

**做法**：把机器人降维成 6D 质心动力学：

```text
A(q) qdd + Adot(q,qd) qd = [m g; 0] + Σ [f_i; p_i × f_i]
```

先解质心任务 + 接触力分配（QP/摩擦锥），再把接触力和关节加速度映射回关节力矩。

**优点**：

- 维度低，适合平衡/行走；
- 接触力显式优化，摩擦锥容易处理；
- 人形/四足平衡的常用结构。

**缺点**：

- 需要接触调度；
- 质心可行不等于全身可行（关节限位/碰撞）；
- 通常要和全身 WBC 级联。

**适合**：浮动基人形/四足的平衡与行走。

**工具**：Pinocchio 的 `data.Ag/hg/dAg`；自己写 QP；或 Crocoddyl 的 centroidal 模型。

**你的阶段**：固定基座不需要；以后解锁轮式底盘时会用到。

---

### 2.5 全身 MPC（Whole-Body MPC）

**做法**：在预测时域内优化状态/控制序列，显式处理动力学、接触、约束；每个控制周期解一次（或热启动）。

**优点**：

- 能预判未来，处理约束和接触切换；
- 平衡/行走性能好；
- 可以统一规划 + 控制。

**缺点**：

- 计算重，实时性挑战；
- 建模/调参复杂；
- 接触序列组合爆炸。

**适合**：浮动基 locomotion、高动态动作。

**工具**：

- **Crocoddyl**：DDP/feasibility-driven，多接触最优控制；
- **Aligator**：ProxDDP，轨迹优化；
- **OCS2**：腿足 MPC；
- **acados**：通用 NLP/MPC。

**你的阶段**：固定基座、慢速操作，MPC 过度；以后做移动/平衡再考虑。

---

### 2.6 学习型 WBC（RL）

**做法**：训练策略网络，输入状态/参考，输出关节目标或力矩；sim-to-real。

**优点**：

- 能处理复杂接触/地形；
- 推理快；
- 不需要手工建模。

**缺点**：

- 可解释性差，安全保证弱；
- 需要大量仿真/奖励设计；
- 参考跟踪精度不如模型法；
- sim-to-real gap。

**适合**：locomotion、复杂地形、难以建模的接触。

**和你的系统结合**：RL 策略可以作为“高层”，输出末端/躯干参考给 WBC；或直接输出关节目标替代 WBC。对固定基座操作，传统 WBC 更可控。

---

### 2.7 阻抗 / 导纳控制

**做法**：不直接跟踪位置，而是模拟“弹簧-阻尼”：

```text
tau = J^T (Kp e + Kd ė) + g(q)
```

导纳控制则用于位置控制型机器人：外力 → 位置修正。

**优点**：

- 交互安全、柔顺；
- 对位置误差不敏感；
- 适合人机协作/接触任务。

**缺点**：

- 跟踪精度取决于刚度；
- 接触稳定性要调阻尼；
- 不是“多任务优化”框架。

**适合**：装配、擦拭、人机交互；可作为 WBC 的任务层或底层。

---

### 2.8 运动学 WBC / 全身 IK

**做法**：只解运动学，求 `qd` 或 `q`，不涉及 `M/h`：

```text
min_{qd} Σ w_i || J_i qd - xd_i* ||²
s.t.     关节限位、速度限位
```

**优点**：

- 简单、快、稳定；
- 不依赖质量/惯量参数；
- 固定基座、慢速操作足够。

**缺点**：

- 不处理动力学/力矩；
- 高速/重载跟踪差；
- 不能做接触力优化。

**适合**：固定基座、准静态、抓取/放置。

**工具**：**Pink**（基于 Pinocchio 的分层 IK）；自己写阻尼最小二乘。

**你的阶段**：如果动作慢，纯 IK 甚至比 WBC 更稳；WBC 的价值在动态/约束/前馈。

---

### 2.9 规划 + WBC 混合（你的当前架构）

**做法**：cuRobo 负责全局、无碰撞、满足关节限位的轨迹；WBC 负责局部跟踪、约束、冗余、前馈。

**优点**：

- 规划层处理全局碰撞/目标；
- WBC 处理局部精度/动态；
- 职责清晰，真机可复用。

**缺点**：

- 两层可能冲突（WBC 修正破坏无碰撞）；
- 需要轨迹混合/重规划；
- 接口/时序要对齐。

**适合**：你现在的系统。**推荐路线：cuRobo + 加权 QP WBC + PD 伺服。**

## 3. 路线对比表

| 路线 | 处理动力学 | 处理不等式 | 多任务优先级 | 计算量 | 典型场景 |
|---|---|---|---|---|---|
| 加权 QP | ✅ | ✅ | 软 | 低 | 固定基座、通用 |
| HQP | ✅ | ✅ | 严格 | 中高 | 人形、多接触 |
| OSC/逆动力学 | ✅ | ❌/弱 | 零空间 | 低 | 机械臂、主任务+姿态 |
| Centroidal | ✅（降维） | ✅ | 接触力层 | 中 | 人形/四足平衡 |
| 全身 MPC | ✅ | ✅ | 代价/约束 | 高 | 高动态 locomotion |
| RL | 隐式 | 隐式 | 奖励 | 推理低 | 复杂接触/地形 |
| 阻抗/导纳 | 部分 | ❌ | ❌ | 低 | 交互/柔顺 |
| 运动学 IK | ❌ | ✅（运动学） | 可分层 | 很低 | 固定基座、慢速 |

## 4. 怎么选

```text
你的机器人是固定基座吗？
├─ 是 → 动作是准静态/慢速吗？
│        ├─ 是 → 运动学 IK 或 加权 QP（加不加动力学前馈看精度）
│        └─ 否 → 加权 QP（含力矩约束）+ 重力/动力学前馈
│                 任务冲突明显/安全关键 → HQP
└─ 否（浮动基/轮式底盘）
         ├─ 需要平衡/行走 → Centroidal WBC 或 全身 MPC
         ├─ 多接触/高动态 → HQP 或 MPC
         └─ 复杂地形/学习 → RL + 传统 WBC 兜底
```

**给你的建议**：

1. 当前固定基座：**加权 QP**，变量 `qdd`，任务 = 左右末端 6D + 躯干 3D + posture，约束 = 关节位置/速度/加速度/力矩。
2. 输出 `q_des/qd_des` 给 Isaac PD；真机同样接口。
3. 等出现任务冲突/安全层级需求，再升级 HQP；等解锁底盘，再加 centroidal/contact。
4. 不要一上来就上 MPC/RL；18 DoF 固定基座用不上。

## 5. 与上层规划的关系

| 规划层 | WBC 层 | 说明 |
|---|---|---|
| cuRobo（全局、无碰撞） | 加权 QP（局部跟踪） | 你的方案 |
| 脚步规划器 | Centroidal/HQP | 人形行走 |
| 遥操作/VR | IK/阻抗 | 主从操作 |
| RL 策略 | 传统 WBC 兜底 | 学习+模型混合 |

规划层给的是**运动学可行**轨迹；WBC 给的是**动力学/约束可行**的关节命令。两者之间需要：

- 时间参数化（速度/加速度连续）；
- 轨迹混合（重规划时平滑切换）；
- 偏差限制（WBC 不要离规划太远，避免碰撞）。

---

## 6. 一页总结

```text
没有“最好的 WBC”，只有匹配场景的 WBC。

固定基座 + 位置 PD：
  加权 QP（推荐） / 运动学 IK（更简单） / HQP（任务冲突时）

浮动基 + 接触：
  Centroidal + 接触力 QP / HQP / 全身 MPC

你的路线：
  cuRobo（规划） → 加权 QP WBC（qdd → q_des/qd_des） → PD 伺服
  先跑通，再按需升级 HQP / 前馈 / 底盘。
```
